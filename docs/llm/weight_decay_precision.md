# 为什么LLM一般使用较大的权重衰减系数？

> 原文作者：Nil-9（复旦大学 计算机技术硕士）
> 原文链接：https://nil9.net/posts/wd-model-precision/

## 核心结论

**权重衰减除了正则化作用外，还能降低精度损失的风险**——对于计算机的浮点数而言，绝对值越大，精度越低。对于低精度/混合精度训练而言，使用权重衰减可以控制参数的绝对值范围，从而保证模型参数不落入低精度的数值区间。

---

## 浮点数的存储与精度

### 浮点数格式

浮点数在计算机内以二进制形式存储，分为三部分：
- **符号位** (sign)
- **指数位** (exponent)
- **尾数位** (mantissa)

常见格式的区别：

| 格式 | 指数位 | 尾数位 | 特点 |
|------|--------|--------|------|
| fp32 | 8位 | 23位 | 单精度，标准训练精度 |
| fp16 | 5位 | 10位 | 半精度，最小间隔 $2^{-10} \times 2^E$ |
| bf16 | 8位 | 7位 | 脑浮点，拓宽范围但降低精度 |

### 关键结论：数值越大，精度越低

对于区间范围 $[2^E, 2^{E+1})$，两个相邻浮点数的最小间隔为：

$$\Delta = 2^{E - \text{mantissa_bits}}$$

**这意味着：**
- 浮点数之间的最小间隔随着绝对值指数级增大
- **bf16相比fp16虽然拓宽了表示范围，但减少了精度**

### 舍入误差问题

当一个大数和小数相加时，由于指数位需要对齐，小数的尾数可能在移位过程中丢失。

**极端示例（fp32）：**
```python
import numpy as np

x = np.float32(2**-1)   # 0.5
y = np.float32(2**-25)  # 约 2.98e-08

result = x + y
print(f"x = {x}, y = {y}")
print(f"x+y = {result}")
print(f"x == x+y? {x==result}")  # True！y 被完全忽略
```

输出：
```
x = 0.5, y = 2.9802322e-08
x+y = 0.5
x == x+y? True
```

在对齐过程中，$2^{-25}$ 需要右移25位，而fp32只有23位尾数，因此**直接变成了0**。

## 对深度模型训练的影响

### 训练过程中的三个风险点

1. **更新失效**：参数绝对值较大 + 更新步幅较小 → 舍入误差导致更新失效
2. **精度转换损失**：高精度模型转为低精度时，参数绝对值越大，丢失精度越多
3. **参数范数增长**：Transformer类模型参数范数随训练逐渐增大（Merrill 2020指出T5参数范数增长正比于 $\sqrt{t}$）

### 混合精度训练的局限

尽管现代混合精度训练会：
- 维护fp32权重备份
- 优化器状态使用高精度版本
- GEMM使用高精度累加器

但仍无法完全避免：
- fp32→低精度的转换损失
- 前向/反向过程中激活值的精度损失

## 权重衰减的作用

### 参数更新公式

$$\theta_{t+1} = \theta_t - \eta \cdot g_t - \lambda \cdot \theta_t$$

其中：
- $\eta$：学习率
- $g_t$：优化器计算的梯度
- $\lambda$：权重衰减系数

### 双重作用

1. **正则化效应**：防止过拟合
2. **精度保护**：控制参数绝对值范围，避免落入低精度数值区间

---

## 实践观察

许多开源LLM在技术报告中都提到使用 **0.1** 作为权重衰减系数，这比传统CV任务中常用的 1e-4 或 1e-5 大得多。

Muon优化器的实验也表明：使用无权重衰减版本训练LLM时，优化器的收敛优势会随着训练过程逐渐消失，侧面印证了权重衰减对LLM训练的重要性。

---

## 总结

从浮点数存储原理出发，建立了「数值越大，精度越低」的结论，从而解释了LLM训练对较大权重衰减系数的依赖：

- 控制参数范数增长
- 降低精度转换损失
- 避免小梯度更新被舍入误差淹没

**注意**：权重范数增长与模型结构相关，这一规律不一定对所有模型都成立。
