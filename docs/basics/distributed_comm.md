# 分布式训练通信原语

> Scatter/Gather/Reduce/AllReduce/Broadcast 等通信操作详解

---

## 通信原语概览

| 原语 | 功能 | 数据流向 | 典型场景 |
|-----|------|---------|---------|
| **Broadcast** | 将源节点数据复制到所有节点 | 一对多（相同数据）| 初始化模型参数 |
| **Scatter** | 将源节点数据分块发送给不同节点 | 一对多（不同数据）| 数据切片并行处理 |
| **Gather** | 将多节点数据收集到目标节点 | 多对一 | 数据并行结果汇总 |
| **Reduce** | 多节点数据聚合后存储到目标节点 | 多对一 | 梯度聚合（需后续广播）|
| **AllReduce** | 多节点数据聚合后分发到所有节点 | 多对多 | 分布式训练梯度同步 |

---

## 详细说明

### 1. Broadcast（广播）

```
节点0: [A] ───────┬───→ 节点0: [A]
        │        ├───→ 节点1: [A]
        │        ├───→ 节点2: [A]
        └────────┴───→ 节点3: [A]
```

**功能**：将单个节点的数据复制到所有节点。

**典型场景**：
- **模型初始化**：主节点加载模型，Broadcast 到所有 worker
- **超参数同步**：将学习率等配置广播到所有节点
- **评估指标**：将全局指标广播到所有节点

**特点**：
- 所有节点接收**相同**的数据
- 通信量：$O(N \times data\_size)$，其中 $N$ 为节点数

---

### 2. Scatter（分散）

```
节点0: [A,B,C,D] ───┬───→ 节点0: [A]
           │        ├───→ 节点1: [B]
           │        ├───→ 节点2: [C]
           └────────┴───→ 节点3: [D]
```

**功能**：将源节点的数据**分块**，发送给不同节点。

**典型场景**：
- **数据并行切分**：将大 batch 数据切分给不同 GPU
- **模型并行**：将模型不同层切分到不同设备
- **MoE 专家分配**：将不同专家分配到不同设备

**特点**：
- 每个节点接收**不同**的数据片段
- 通信量：$O(data\_size)$
- 与 Broadcast 区别：Broadcast 是全量复制，Scatter 是切分分发

---

### 3. Gather（收集）

```
节点0: [A] ──┐
节点1: [B] ──┼──→ 节点0: [A,B,C,D]
节点2: [C] ──┤
节点3: [D] ──┘
```

**功能**：将多节点的数据**收集**到目标节点。

**典型场景**：
- **结果汇总**：收集各设备的推理结果
- **梯度收集**（非 AllReduce 场景）：先 Gather 再 Reduce
- **日志收集**：收集各节点的训练日志

**特点**：
- Scatter 的逆操作
- 通信量：$O(data\_size)$
- 目标节点内存压力较大

---

### 4. Reduce（归约）

```
节点0: [A] ──┐
节点1: [B] ──┼──(sum)──→ 节点0: [A+B+C+D]
节点2: [C] ──┤
节点3: [D] ──┘
```

**功能**：多节点数据**聚合**（如求和、求平均、取最大）后存储到**目标节点**。

**常见操作**：
- **SUM**：求和（梯度累加常用）
- **MEAN**：平均
- **MAX/MIN**：取最大/最小值
- **PROD**：乘积

**典型场景**：
- **梯度聚合**：将各节点的梯度求和到主节点
- **BatchNorm 统计**：聚合各设备的 mean/var

**特点**：
- 结果只存在于**目标节点**，需要后续 Broadcast 才能同步
- 通信量：$O(data\_size)$

---

### 5. AllReduce（全归约）⭐

```
节点0: [A] ──┐               ┌──→ 节点0: [A+B+C+D]
节点1: [B] ──┼──(sum)──┬──→ ├──→ 节点1: [A+B+C+D]
节点2: [C] ──┤        ├──→ ├──→ 节点2: [A+B+C+D]
节点3: [D] ──┘        └─→ └──→ 节点3: [A+B+C+D]
```

**功能**：多节点数据**聚合**后**分发**到所有节点。

**本质**：**Reduce + Broadcast** 的组合优化

**典型场景**：
- **梯度同步**：分布式训练中最核心的操作
- **Ring-AllReduce**：大规模训练的高效实现

**特点**：
- 所有节点最终获得**相同**的聚合结果
- 通信量：$O(data\_size)$（优化后）
- 是分布式训练的**性能瓶颈**

## 通信原语对比

### 数据流向对比

| 原语 | 示意图 | 说明 |
|-----|-------|------|
| **Broadcast** | 1→N（相同）| 一个节点发，所有节点收相同数据 |
| **Scatter** | 1→N（不同）| 一个节点发，各节点收不同片段 |
| **Gather** | N→1 | 各节点发，一个节点收所有 |
| **Reduce** | N→1（聚合）| 各节点发，一个节点收聚合结果 |
| **AllReduce** | N→N（聚合）| 各节点发，所有节点收聚合结果 |

### 通信量对比

| 原语 | 通信量 | 说明 |
|-----|-------|------|
| **Broadcast** | $O(N \times S)$ | 发送 $N$ 份完整数据 |
| **Scatter** | $O(S)$ | 发送 $N$ 份分片，总量不变 |
| **Gather** | $O(S)$ | 收集 $N$ 份分片 |
| **Reduce** | $O(S)$ | 收集并聚合 |
| **AllReduce** | $O(S)$ | 优化算法（Ring/Pipeline）|

## 分布式训练典型流程

### 数据并行训练

```
前向传播：
    数据 ──Scatter──→ 各 GPU
    模型 ──Broadcast─→ 各 GPU

反向传播：
    梯度 ──AllReduce─→ 同步梯度

参数更新：
    各 GPU 独立更新（相同梯度→相同更新）
```

### 模型并行训练

```
模型切分 ──Scatter──→ 各 GPU
输入数据 ──Scatter──→ 各 GPU（按层传递）
中间结果 ──Point-to-point──→ 层间传递
梯度回传 ──Point-to-point──→ 反向传递
```

### ZeRO-1 优化

```
参数分片 ──Scatter──→ 各 GPU（只存部分参数）
前向时 ──AllGather──→ 临时收集完整参数
反向时 ──ReduceScatter──→ 分片存储梯度
```

## AllReduce 算法优化

### Ring-AllReduce

```
Step 1: Scatter-Reduce（环状传递）
    GPU0: [A0] ← [A1] ← [A2] ← [A3]
    GPU1: [B0] → [B1] ← [B2] ← [B3]
    GPU2: [C0] → [C1] → [C2] ← [C3]
    GPU3: [D0] → [D1] → [D2] → [D3]
    
Step 2: AllGather（环状广播）
    每个 GPU 将自己的 chunk 广播给所有其他 GPU

总通信量: 2(N-1)/N × data_size ≈ 2 × data_size
```

**特点**：
- 带宽最优
- 延迟与 GPU 数成正比
- 适合大规模集群

### Tree-AllReduce

```
二叉树结构聚合
Level 1: GPU0↔GPU1, GPU2↔GPU3
Level 2: GPU0↔GPU2

总通信量: 2 × log(N) × data_size
```

**特点**：
- 延迟最优
- 适合小集群、高延迟网络

## 面试要点

### 常见问题

**Q1: Broadcast 和 Scatter 的区别？**
- A: Broadcast 是所有节点收**相同**数据；Scatter 是各节点收**不同**分片

**Q2: Reduce 和 AllReduce 的区别？**
- A: Reduce 只把结果存到**目标节点**；AllReduce 把结果**同步到所有节点**

**Q3: 为什么分布式训练用 AllReduce 而不是 Reduce+Broadcast？**
- A: AllReduce 是优化的组合操作，通信量相同但延迟更低（Ring-AllReduce 算法优化）

**Q4: Scatter/Gather 与 Reduce 的区别？**
- A: Scatter/Gather 只做数据搬运，不做计算；Reduce 还会做聚合计算（如求和）

**Q5: 数据并行中最核心的通信操作是什么？**
- A: **AllReduce**（梯度同步），通常占训练时间的 10%~50%

**Q6: Ring-AllReduce 的通信量是多少？**
- A: 约 $2 \times data\_size$（与 GPU 数 $N$ 无关，只与数据量有关）

## 总结

```
Broadcast: 1 → N (相同数据)    [初始化]
Scatter:   1 → N (不同分片)    [数据并行]
Gather:    N → 1 (收集)        [结果汇总]
Reduce:    N → 1 (聚合)        [梯度聚合]
AllReduce: N → N (聚合+广播)   [梯度同步，最常用]
```

**核心记忆**：
- **B**roadcast = **B**ig data to all（全发）
- **S**catter = **S**plit and send（拆分）
- **G**ather = **G**et together（收集）
- **R**educe = **R**educe to one（归约）
- **All**Reduce = **All** get reduced result（全同步）
